# Office UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A no-build web UI served by the orchestrator: pixel office with live/replayed team interactions, chat with the Manager, task-flow tree, filterable log, role detail, approvals, workspace and run pickers.

**Architecture:** `ui/` static files (HTML/CSS/ES modules). `ui/js/state.js` is a pure reducer over TeamEvents (Node-testable). `office.js` renders desks/characters/effects from state; `panels.js` renders side panels; `app.js` wires API, SSE, replay.

**Tech Stack:** vanilla JS (ES2022 modules), CSS, `marked@<installed version>` (pinned direct dep), Node `node:test` for reducer + server routes.

**Spec:** `docs/superpowers/specs/2026-10-20-office-ui-design.md`

## Global Constraints
- No build step; files under `ui/` load directly in the browser.
- Keep server Host/Origin checks; only add the server's own origins.
- Same portable Node / env rules as the orchestrator plan.
- Every non-delta event must be reachable in the Log view.

## Review Focus
1. Page opened mid-run → current state reconstructed (replay + SSE, no duplicate events). (Task 2 test `merge dedupes by seq`.)
2. Approval answered from the UI → disappears for everyone, role leaves `approval`. (Task 2 test `approval lifecycle`.)
3. Path traversal on `/ui/..%2f..%2fpackage.json` → 404. (Task 1 test.)
4. Workspace with a subset of roles → only those desks render. (Task 3 manual check + `deskLayout` test.)
5. Long Manager replies with Markdown/HTML → rendered safely (no script execution). (Task 4: sanitize — escape raw HTML before `marked`.)
