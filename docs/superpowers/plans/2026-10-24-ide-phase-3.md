# Kế hoạch Triển khai Chi tiết Giai đoạn 3: Xem Thay Đổi (Diff) theo Từng Lần Chạy qua Shadow Backup

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Triển khai Giai đoạn 3 của Minimalist Embedded IDE: Hệ thống theo dõi thay đổi mã nguồn theo từng lần chạy (run-based diff) sử dụng cơ chế Shadow Backup tự động. Hook can thiệp vào `tool_call` (trong `pi-runner.ts`) để sao lưu file gốc ngay trước khi role gọi `write` hoặc `edit`, lưu trữ tại `<workspace>/.company/shadow/<runId>/`, quản lý hạn mức 256KB/file, tổng 20MB theo cơ chế FIFO xoay vòng, tuyệt đối không làm gián đoạn role; thuật toán Myers Diff thuần TypeScript (giới hạn 10.000 dòng); API server bảo mật `GET /changes` và `GET /diff`; giao diện UI gồm mục "Thay đổi" trên Activity Bar, danh sách file A/M, tab Diff trực quan xanh/đỏ và lan truyền huy hiệu trên Explorer.

**Architecture:**
- **Thuật toán Myers Diff (`src/diff.ts`):** Module diff thuần TypeScript tính toán shortest edit script giữa hai chuỗi văn bản, xuất ra cấu trúc dòng `add` / `del` / `eq`, đánh số dòng cũ/mới, giới hạn bảo vệ 10.000 dòng.
- **Shadow Backup Engine (`src/shadow.ts`):**
  - Chặn ngay trước khi `write`/`edit` thực thi: nếu file chưa từng được chụp trong run hiện tại, kiểm tra sự tồn tại của file.
  - File mới chưa tồn tại trên đĩa → ghi nhận trạng thái `"A"` vào `.manifest.json`.
  - File đã tồn tại (text <= 256KB) → sao chép file gốc sang `<workspace>/.company/shadow/<runId>/<relPath>` và ghi nhận trạng thái `"M"`.
  - Quota Manager: tính tổng dung lượng thư mục `.company/shadow/`, nếu vượt quá 20MB thì xoá thư mục của các run cũ nhất theo thứ tự FIFO.
  - Bọc toàn bộ trong `try/catch`: nếu lỗi đĩa/hết quyền, ghi log cảnh báo và tiếp tục cho role ghi file bình thường.
- **Hook trong `src/pi-runner.ts`:** Tích hợp `captureShadowBeforeToolCall` vào extension handler `pi.on("tool_call")`.
- **API Server (`src/server.ts`):**
  - `GET /workspaces/:id/changes?runId=...`: Trả về danh sách `{ path, status: "A"|"M" }`.
  - `GET /workspaces/:id/diff?path=...&runId=...`: Thẩm định đường dẫn qua `assertSafeWorkspacePath` (chặn traversal `../`, symlink escape, file bí mật), đọc bản shadow và bản đĩa hiện tại, chạy Myers Diff và trả về kết quả.
- **Frontend UI (`ui/index.html`, `ui/styles.css`, `ui/js/ide/diff.js`, `ui/js/ide/tree.js`, `ui/js/app.js`):**
  - Activity Bar: Thêm icon "Thay đổi" (`#act-changes`), nhấp mở Sidebar Thay đổi (`#sidebar-changes`).
  - Sidebar Thay đổi: Bộ chọn lần chạy (run selector), thông báo giới hạn ("chỉ theo dõi file đội sửa bằng công cụ write/edit"), danh sách file A/M.
  - Tab Diff trong Editor: Render dòng xanh lá (`+`) / đỏ (`-`) với số dòng cũ/mới, nút "Mở file trong Editor".
  - Explorer Badges: Gắn huy hiệu `A` / `M` trên file và lan truyền chấm màu lên các thư mục cha.

**Tech Stack:** Node.js >= 22.19, TypeScript (erasable syntax), `node:test`, `node:assert/strict`, Vanilla HTML5/CSS3/ESM. Zero external dependencies.

## Review Focus & Failure Modes
1. **Khả năng chịu lỗi tuyệt đối của Shadow Hook:**
   - Nếu ổ đĩa bị đầy, quyền ghi bị từ chối hoặc shadow gặp exception bất kỳ, hàm `captureShadow` không bao giờ được phép ném lỗi ra ngoài làm sập session hoặc hủy bỏ công cụ `write`/`edit` của role.
2. **Nguyên tắc chụp duy nhất lần đầu trong một Run:**
   - Trong một run, nếu AI gọi `write` lần 1 (sửa nội dung) rồi tiếp tục gọi `edit` lần 2, bản shadow chỉ được chụp ở lần 1 (bản gốc trước run), không được chụp đè lần 2.
3. **Quản lý hạn mức Quota FIFO 20MB:**
   - Khi tổng dung lượng shadow backup vượt quá 20MB, hệ thống phải tự động xóa các thư mục run cũ nhất theo mtime/creation time cho đến khi tổng dung lượng < 20MB.
4. **Bảo mật Path Jail & Chặn Secret trên API Diff:**
   - Truy vấn `GET /diff?path=../../etc/passwd` hoặc `path=.env` phải bị `assertSafeWorkspacePath` chặn đứng với mã lỗi 403 Forbidden.
5. **Hiệu năng Myers Diff với file lớn:**
   - Giới hạn 10.000 dòng code. Nếu một trong hai file vượt quá 10.000 dòng, không chạy đệ quy ma trận diff để tránh treo CPU Node.js, thay vào đó trả về `truncated: true` kèm thông báo tóm tắt.
